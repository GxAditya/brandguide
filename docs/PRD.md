# PRD: BrandKit

Live brand guide extraction from any company name or URL.

- **Bounty:** TinyFish "Brand Guide Generator"
- **Status:** Shipped
- **Owner:** aditya
- **Licence:** MIT

---

## 1. Problem

Marketers need a machine readable brand kit for any company. Today that means
paying an agency, asking a designer, or pasting screenshots into a chat window.

Existing "brand colour scrapers" grab one hex value from the homepage and stop.
They return a screenshot, not an object.

The useful product is a **structured, evidence backed object** a marketer can
push into Figma, Tailwind, or a brand service, where every value carries the URL
it came from.

## 2. What is built

A zero dependency Node service plus a single page web UI that turns a URL or a
company name into a structured brand guide, extracted from the live site.

The output is not prose. It is a versioned JSON object validated against a
published schema, plus renderings as Markdown, CSS custom properties, a Tailwind
theme, Style Dictionary JSON, Figma Variables, and an SVG swatch sheet.

The guide renders as a paged document set in the brand's own colours and
typefaces.

### Non-goals

- Not a logo regeneration tool. Returns **verified live asset URLs**, never
  redrawn marks.
- Not a CMS. Guides are ephemeral, nothing is persisted.
- Not an LLM wrapper. Colour, type, and logo are extracted deterministically from
  fetched bytes and are **never** generated by a model.
- Not a CLI. The product is a frontend and a backend over HTTP.

## 3. TinyFish is the entire read layer

Every byte of the target site enters through TinyFish. There is no direct
`fetch()` of the target site, no headless browser in the default path, and no
scraping library. `src/tinyfish/client.js` is the only module that opens a socket
to a target site.

Two surfaces are used, both free at any balance, so the default path costs
nothing.

| Surface | Endpoint | Method | Role |
| --- | --- | --- | --- |
| Search | `https://api.search.tinyfish.ai/` | `GET` | Resolve a company name to its official domain. Find competitors for the compare endpoint |
| Fetch | `https://api.fetch.tinyfish.ai` | `POST` | Read the document head, every stylesheet, content pages, manifests, and image assets |

Both are overridable with `TINYFISH_FETCH_URL` and `TINYFISH_SEARCH_URL`.

### Five load bearing uses

| What | How | Result |
| --- | --- | --- |
| Name to domain | `Search` with `query` | Ranked results, scored on URL parts, hosted profile platforms rejected |
| Brand metadata | `Fetch` with `include_selectors: ["head"]`, `format: "html"` | The `<head>` **verbatim**: og tags, theme colour, icon links, manifest, and every stylesheet URL |
| Design tokens | `Fetch` on each stylesheet URL | Raw CSS as text, so declarations and `@font-face` rules are readable |
| Copy across pages | `Fetch` with `format: "html"`, `links: true`, `image_links: true` | Cleaned semantic HTML with absolute URLs |
| Logo existence | `Fetch` on the candidate URL | `empty_content` means it resolved, `page_not_found` means it is rejected |

Two decisions carry the whole product:

- **`include_selectors: ["head"]` is the critical call.** By default Fetch returns
  cleaned semantic HTML with `<head>`, `<style>`, and `<link>` stripped, which is
  ideal for reading copy and useless for reading a brand. Scoping the same fetch to
  the head returns it verbatim, so one call yields every piece of first party
  metadata a site publishes about itself plus its full stylesheet list.
- **Fetch renders in a real browser, so its error code proves an asset exists.**
  For an image URL, `empty_content` means it resolved and has no text to extract.
  The absence of text is the proof of existence, which is how a dead logo link is
  never returned.

Fetch renders, so a JavaScript heavy SPA reads as well as a static site. Browser
and Agent are deliberately unused: they are metered, and Fetch already covers it.

### On the LLM question

TinyFish has four surfaces, Search, Fetch, Browser, and Agent, and **none of them
is a language model**. Agent automates a browser, it does not write prose. So the
two jobs are separated:

- **Deterministic core, always on, no model.** Colour, WCAG contrast math,
  CIEDE2000, type families, weights, logo verification, token graphs, and a
  lexical voice profile are computed locally from fetched bytes. Reproducible,
  auditable, free.
- **Optional interpretation layer**, BYO key. Upgrades **narrative** only: the
  tone paragraph, message pillars, positioning line, writing guidance. Every
  sentence must carry a source URL. The output is a separate block that is
  structurally unable to overwrite colour, type, or logo, which are attached
  after generation.

The app is fully functional with no LLM key. That is the default, and it is how
the tests and the demo run.

## 4. Endpoints

Two endpoints, plus supporting routes.

| Method | Path | Returns |
| --- | --- | --- |
| `POST` | `/api/v1/brand-guide` | The complete brand guide. Also over `GET` so a guide can be linked to |
| `POST` | `/api/v1/compare` | Benchmark of 2 to 5 live brands |
| `GET` | `/api/v1/stream` | Server sent events, so the UI shows each source as it is read |
| `GET` | `/api/v1/health` | Liveness and the credential header names. Makes no upstream call |
| `GET` | `/api/v1` | The narration provider catalogue. Authoritative |
| `POST` | `/api/v1/llm-check` | One minimal request against a narration credential |
| `GET` | `/` | The UI |

`?format=` applies to brand-guide and compare only: `json`, `markdown`, `css`,
`tailwind`, `styledictionary`, `figma`, `svg`.

`GET /api/v1/health` is liveness only and never touches a key, so a platform
health check can point at it safely. Whether your key works is answered by the run
that used it.

### 4.1 `POST /api/v1/brand-guide`

Request: `{ input, depth?, pages?, narrate? }`

- `input` is a URL (`"linear.app"`) or a company name (`"linear"`). Names are
  resolved with Search.
- `depth` is `quick` (0 content pages), `standard` (5, the default), or `deep` (10).
- `pages` is 4 to 24, default 14. It sets the length of the **full document** and
  only applies when narration is configured.

Pipeline: `Search` if the input is a name, then `Fetch` the head, `Fetch` the
stylesheets, `Fetch` 4 to 8 content pages, then compose.

Response, abridged:

```jsonc
{
  "schemaVersion": "1.0.0",
  "generatedAt": "2026-10-02T18:00:00.000Z",
  "input": { "given": "linear", "resolvedUrl": "https://linear.app", "resolvedBy": "search" },
  "identity":   { "name": "tailwindcss", "domain": "tailwindcss.com" },
  "logos":      { "primary": { … }, "lockup": { … }, "alternates": [ … ], "rejected": [ … ] },
  "colors":     { "tokens": [ … ], "roles": { … }, "contrast": [ … ], "neutralRamp": { … } },
  "typography": { "families": [ … ], "scale": [ … ], "pairing": { "heading": "Inter Variable" } },
  "voice":      { "vector": { … }, "do": [ … ], "dont": [ … ] },
  "messaging":  { "pillars": [ … ], "taglines": [ … ], "boilerplate": [ … ] },
  "narrative":  { … },              // only when a narration layer ran
  "llm":        { "enabled": false },
  "confidence": { "overall": 0.74, "bySection": { … } },
  "deck":       { "requestedPages": 14, "defaultPages": 14 },
  "provenance": { "tinyfish": { "calls": [ … ] }, "pagesRead": [ … ], "stylesheetsRead": 49, "methods": { … } },
  "warnings":   [ ]
}
```

### 4.2 `POST /api/v1/compare`

Request: `{ input, competitors: [] }`, 2 to 5 brands.

Search finds each competitor's official domain, then every brand goes through the
same pipeline as the brand guide. The diff is CIEDE2000 palette distance, font
overlap, cosine distance between tone vectors, Jaccard overlap of message pillars,
and token sharing.

Returns a whitespace analysis and a ranked list of what is genuinely distinctive
about the brand.

## 5. Requirements and constraints

| Requirement | Status |
| --- | --- |
| Runtime dependencies: 0 | Met. `node_modules` does not exist |
| Works for any public site, no hardcoded domains, brands, or selectors | Met |
| Every value traceable to a source URL | Met |
| Graceful degradation, per URL fetch errors collected and never fatal | Met |
| Secrets never logged, never returned | Met. Keys arrive per request in headers, so the server stores none at all |
| Cold start under 100 ms | Unmeasured. No test or benchmark asserts it |
| Single guide under 45 s wall clock | Unmeasured. The only per run timing in code is per call `durationMs` in the provenance block |

The two timing rows were targets, not results. Nothing measures them.

### Upstream constraints

- Fetch accepts 10 URLs per call, and roughly 150 URLs per minute per key.
- Fetch has a 120 s CDN ceiling per batch. The client timeout is 150 s.
- Stylesheets are capped at 2 MB each, and at 50 per run at `standard` depth, 60
  at `deep`.
- Stylesheet batches run two at a time. Firing all five at once once lost a third
  of them and took the `@font-face` rules with them.
- The client honours `Retry-After` and retries with jittered backoff.
- Private IPs and localhost are rejected upstream, so SSRF is TinyFish's boundary.

## 6. Accuracy strategy

The criterion is *extracted details are accurate to the live site*.

1. **Ground truth over inference.** If `<meta name="theme-color">` says `#08090a`,
   that is the background token. Not a guess from a frequency count.
2. **Declared intent beats frequency.** `--color-brand-bg` outranks a hex that
   appears 40 times in a stylesheet. On a Tailwind site white is used more than
   any brand colour, so "used most" is not "the brand colour". Tokens are tiered by
   namespace before scoring, so a component token can never win.
3. **Translucent overlays are excluded.** Alpha below 0.6 is counted and discarded.
   Without this, `--header-border: #00000014` became a solid black border.
4. **Icon fonts and escaped class names are rejected.** Patagonia ships
   `patagonia-icons` as its only `@font-face`, and a genuine copy paste bug of
   `font-family: object-fit\: cover`.
5. **Verify, never assume.** A logo URL is only returned if Fetch confirms it
   resolves.
6. **Never let the model invent.** Interpretive output is a separate block that
   cannot overwrite an extracted fact.
7. **Show the receipts.** Every value carries a source. The response body carries
   every TinyFish call with its latency, and the UI shows the pages it read.
8. **Confidence per section**, derived from how many independent sources agreed.
   Anything inferred is labelled `inferred` in the output and the UI.

## 7. UI

Single page, no build step, served as written.

The differentiator: **the guide renders as a paged document set in the brand's
own colours and typefaces.** A marketer sees the guide, and sees it in the identity
it documents.

The document is a fixed 1200x900 landscape canvas scaled to fit, so the same page
looks identical on a laptop and a projector, and prints one landscape sheet per
page. The layout follows the conventions of a real guidelines document: a two
column running header carrying the source domain, a rule, then content.

Two outputs, chosen in the rail: **Guide** and **Compare**.

Composer at the top of the stage. Rail on the left: output mode, compare against,
guide length, read depth, examples. Output: the deck, with a document header
carrying name, domain, confidence, page count and stylesheet count, then the
export strip.

While a run is live, the sources read appear in a modal that closes itself when
the pipeline does. A permanent telemetry panel is not shipped. The same facts are
one line in the document header, and the full per call provenance is in the
response body.

Exports render in the browser from the guide already in memory, using the same
renderers the API serves, so exporting costs no crawl.

### 7.1 Two output modes

The deck renders one of two documents, decided by whether narration produced
content.

**Deterministic, no LLM key, the default. Seven pages at most, never more.**

Cover · Logomark · Logotype · Color Palette · Typeface · Weights · Type Scaling

Five of the seven are emitted only when the data exists, so a thin site gets fewer.
Every one is a measurement: a verified asset URL, a resolved hex, an `@font-face`
declaration, a size the site actually uses. None of it is written, because a brand
cannot be summarised from a hex value. The prose on those pages describes the
extraction, not the brand.

**Narration configured. The full document.**

Contents, About the brand, Positioning, Message pillars, Tone of voice, Aim and
vision, Asset register, Combinations, Writing in this voice, Sources read, and
Confidence, each opened by a section plate. `pages` sets the length of this
document. The model is structurally barred from colour, type and logo values, so
it can fill pages but never alter a measurement.

A page is emitted only if it can be filled truthfully. Nothing is padded to hit a
number, and a shortfall is stated on the page rather than hidden.

### 7.2 The brand name, and which logo

The cover carries the brand name at 76px, which makes it the most conspicuous value
in the document. It is always the **fetched** name, resolved from the site's own
metadata, never the URL that was pasted in. The name is set in the brand's **own
capitalisation**: `tailwindcss` is never rendered as `TAILWIND CSS`, because the
casing is part of the identity.

The best *mark* and the best *lockup* are usually different assets, so both are
returned.

| | `logos.primary` | `logos.lockup` |
| --- | --- | --- |
| Chosen by | SVG first, then highest score | Declared aspect ratio 2.2 or wider, then a logo-ish filename, then the og:image |
| Usually | The app icon | The mark plus wordmark |
| Used on | The Logomark page | The Cover only |

`lockup` is `null` when the two are the same asset, so a consumer can tell "none
found" apart from "same file".

This split exists because of Tailwind: the SVG in its head is a dark rounded
square, which outscores everything and is invisible on a dark plate, while the
real logo is a wide asset in the page body.

### 7.3 The document is always light

The paper and the ink are fixed and never taken from the brand. A guide that
inherits a dark brand's background stops being a document and becomes a screenshot
of that brand's site, and a print of it comes out as a book of black pages.

What the brand does change is the type the document is set in, and the colour of
every swatch, plate, and specimen drawn on the page.

### 7.4 Logos keep their colour

A logo loaded through `<img src="…svg">` cannot inherit anything from the page,
and a large share of real brand SVGs are built to inherit: `fill="currentColor"`
is how most design systems ship one file that works on light and dark. Loaded as
an image, `currentColor` resolves against the SVG's own default, so a cyan Tailwind
mark arrives flat black. That was never a filter or a bad asset, just an image
boundary doing what images do.

So the extractor reads the SVG source through Fetch and returns it as
`logos.primary.svg`, sanitised. The deck inlines that markup rather than pointing
an `<img>` at the URL, so `currentColor` resolves against the page and the real
colours come through.

Two consequences:

- **Inlining remote markup is a script injection risk, so it is stripped.**
  Scripts, event handlers, external `href`, external `url()` paint servers,
  DOCTYPE and ENTITY declarations, and `javascript:` are all removed before the
  source leaves the server. The deck parses with `DOMParser` and adopts nodes one
  at a time, never assigning to `innerHTML`.
- **The surface follows the asset.** `svgTone` reads the mark's own fills and
  gradient stops and reports `light`, `dark`, or `inherit`. A white mark is shown
  on a dark plate and a dark mark on a light one, because a white mark on a white
  page is the same class of bug as the greyscale one.

The **Logotype** page deliberately does not show the lockup. A logotype is the
wordmark on its own, so that page sets the name in the brand's heading face inside
a bordered box, which is what the reference deck does. The mark has already been
shown on the page before it.

## 8. Narration providers

Optional, BYO key, nine presets. Five free tiers need no payment method.

| Preset | Free | Default model |
| --- | --- | --- |
| `gemini` | yes | `gemini-3.1-flash-lite` |
| `openrouter` | yes | `openrouter/free` |
| `groq` | yes | `openai/gpt-oss-120b` |
| `nvidia` | yes | `nvidia/nemotron-4-340b-instruct` |
| `cerebras` | yes | `gpt-oss-120b` |
| `openai` | no | `gpt-6.1-sol` |
| `mistral` | no | `mistral-medium-latest` |
| `deepseek` | no | `deepseek-flash` |
| `custom` | no | Any OpenAI compatible `/chat/completions` server |

Gemini is called on its own API, not the OpenAI shape, because Google does not
serve `/chat/completions` on its own domain. The request goes to
`POST https://generativelanguage.googleapis.com/v1beta/interactions` with an
`x-goog-api-key` header, and the narrative is requested as JSON by schema rather
than by asking nicely in the prompt.

Provider model ids rotate constantly and a retired id costs a whole run. The lists
are checked against each provider's own model list, most recently on 7 October
2026. `GET /api/v1` returns whatever the server currently holds and is
authoritative. Re-check rather than trust a hardcoded list.

Two failure shapes are kept apart, because treating them the same was a real bug:

- **Refused**, 400, 404, or 422: an unsupported field or a retired model id. The
  same call is retried shedding one optional field.
- **Unavailable**, 429 or 5xx: a smaller body cannot help, and trying one would
  spend the caller's quota to prove it. The identical request is retried with
  backoff, and on Gemini the ladder moves to a different model.

## 9. Credential handling

The server holds no credentials. A deployment is a public URL and nothing else.

- Each caller sends their own key with their own request, so two people on one
  instance spend their own quota and there is nothing stored to leak or rotate.
- Keys arrive in headers, not the query string, because a secret in a URL lands in
  proxy logs and browser history.
- Headers rather than a body, because the live progress endpoint is a `GET` and an
  `EventSource` cannot carry one.
- The server logs a request path and an error code on failure, never headers and
  never bodies.
- The browser is the only place a key can exist. It lives in `localStorage`,
  falls back to memory when storage is refused, and the settings panel says so
  rather than pretending the save will outlive the tab.
